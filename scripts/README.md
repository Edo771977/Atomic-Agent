# Build and maintenance scripts

Status: current
Owner: scripts/

Read [AGENTS.md](AGENTS.md) before script changes. [Bundling](docs/bundling.md) owns SEA/assets/signing/release details, including the Linux deb/rpm/AUR packages ([linux-packages.ts](linux-packages.ts)), their apt/dnf repository ([linux-repo.ts](linux-repo.ts)), the pure naming/layout module ([linux-packaging.ts](linux-packaging.ts), tested by vitest from `scripts/`) and the container smoke ([smoke-linux-package.sh](smoke-linux-package.sh)). [Document checker](check-docs.mjs) is offline and validates active documentation; its self-test uses temporary fixtures. TypeScript script checks use tsconfig.scripts.json; production lint excludes scripts. Do not invoke release/signing/upload scripts merely to check documentation.

[Test types](check-test-types.mjs) reject new diagnostics against the explicit ledger; [self-test](check-test-types.selftest.mjs) uses temporary fixtures. [Test runner](run-tests.mjs) shares the quarantine registry with CI; [registry self-test](run-tests.selftest.mjs) verifies exclusions and workflow checks. See [local verification](../docs/testing/local-ci.md).

[Import checker](check-imports.mjs) resolves production dependencies with TypeScript, checks ownership even for type-only imports, and rejects runtime cycles. [Self-test](check-imports.selftest.mjs) uses disposable projects. [Boundary policy](../docs/architecture/import-boundaries.md) records scope and limitations.

[Offline process smoke](smoke-e2e.mjs): after `npm run build`, run `npm run smoke:e2e` (optional `-- --output /tmp/atomic-e2e-report`). It starts actual built CLI/sidecar processes, a loopback scripted LLM server and disposable state/workspaces. Assertions cover tools, approvals, streaming, repair, FIFO, steering, cancellation, persistence and clean exit. No credentials or model downloads are needed. It requires permission to bind localhost. See [the smoke report](../docs/testing/e2e-smoke.md) for the separately performed CLI, native provider and PTY checks and the limits of canned completions.

[Fixture generation](generate-fixtures.ts) refreshes committed extractor fixtures only when run directly. Pass an output directory (`npx tsx scripts/generate-fixtures.ts <directory>`) or call `generateFixtures(directory)` to generate disposable fixtures; importing the module performs no writes. Its regression test uses a temporary directory and preserves committed fixtures.

[models.dev snapshot](generate-models-dev-snapshot.ts): `npm run models:snapshot` refetches https://models.dev/api.json and rewrites `src/llm/provider/models-dev/models-dev-snapshot.ts`, keeping only the services listed in `models-dev-ids.ts` and only context/output limits and prices. The file records its `MODELS_DEV_SNAPSHOT_DATE` (the committed one is from 2026-11-12), which the usage report shows beside costs estimated from it; snapshot prices only ever estimate spend and never make a turn cap or daily limit hard. It and the two Anthropic scripts below are the only ones here that reach the network; run it by hand and review the diff (ATO-647). Zero cache rates are omitted (they then price at the input rate) and models.dev's `context_over_200k` tier becomes `pricing.longContext`; the committed snapshot predates that mapping (its zero cache rates were removed by hand), so it carries no long-context tiers until the next regeneration.

[Anthropic price check](check-anthropic-prices.ts): `npm run prices:anthropic` fetches the official pricing page (https://platform.claude.com/docs/en/about-claude/pricing, its `.md` variant, else the HTML), parses the "Model pricing" table (base input, 5-minute cache write, cache hit, output; the Haiku 5.5 "for prompts over 100,000 tokens" row as `longContext`) and the "Fast mode pricing" table (as a multiple of the base rate), and compares them with the generated block of `src/llm/provider/official-prices/anthropic-official-prices.ts`. It prints added, removed and changed rows; exit 0 means the table matches, 1 that it differs, 2 that the page could not be read or parsed or a model name is not mapped (unknown names are reported, never guessed; add the family to `mapModelName`). Retired rows are skipped. `-- --write` regenerates only the block between the `BEGIN GENERATED`/`END GENERATED` markers and moves `ANTHROPIC_OFFICIAL_PRICES_DATE` to today; review the diff. A write that fails (the file cannot be read, rewritten or saved) exits 4 with the reason. `-- --source <saved .md or .html>` reads a saved copy. It refuses to fetch in offline mode. The test parses a trimmed saved copy (`test-fixtures/anthropic-pricing-2026-11-15.md`) and never reaches the network. `/usage` says "price list from <date>; check <official pricing page>" once the table date is more than 90 days old (the page, not this script, which needs a source checkout).

[Anthropic live smoke](smoke-anthropic.ts): `npm run smoke:anthropic` checks the native Anthropic provider against the real API with the owner's own `ANTHROPIC_API_KEY` (PowerShell: `$env:ANTHROPIC_API_KEY="..."; npm run smoke:anthropic`); it is not part of `npm test` or CI. Without the key it prints "skipped: ANTHROPIC_API_KEY is not set" with how to set it and exits 3 (skipped, so a wrapper never reads it as a pass); in offline mode it exits 2 without sending anything. It runs prompt caching (PASS when the second identical request reads from the cache), a one-tool round trip and an effort low/medium comparison on `claude-haiku-5-5` (`-- --model <id>` for another model in the official table), then prints the run's cost at the official prices. It refuses to start when the worst-case cost exceeds $0.25 unless `-- --max-usd <amount>` raises the cap, and stops once spend passes the cap. The key is never printed. Exit 1 means a check failed. Its unit test covers only argument parsing, the budget and the verdicts. See [how to verify on your machine](../src/llm/docs/anthropic-messages.md#how-to-verify-on-your-machine).
