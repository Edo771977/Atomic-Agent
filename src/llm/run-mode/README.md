# Local, Cloud and Fusion resolution

Status: current
Owner: src/llm/run-mode/

The resolver derives the effective mode from live provider configuration and validated pins. A stored mode label alone does not guarantee that its designated orchestrator is active. Switching providers re-resolves behavior; worker and orchestrator provider kind/id validation belongs to config.

Read [LLM instructions](../AGENTS.md), [resolver](resolve-run-mode.ts), [fusion setup planner](fusion-setup-plan.ts) (`setup fusion`), [resolver tests](resolve-run-mode.test.ts), [run-mode schema](../../config/llm-run-mode-config.ts), and [workers](../../tools/fusion/README.md).

[Fusion team](fusion-team.ts) (issue #37) holds the pure helpers behind `llm.runMode.fusion.team`: `parseTeamMember` / `teamMembers` (members are `providerId:model`, compared by the whole ref), `memberFamily` / `teamFamilyOf` (anthropic, openai, local, other, from the provider kind), `memberReachable` over `TeamReachabilityFacts` (filled from `detectFusionSetup` by `teamFactsFromSetup`, or by the TUI from its own status; only a member known to be broken is unreachable), `filterByPolicy` (folder provider constraints, directors included), the picks `defaultDirector`, `defaultWorker` and `pickReviewer` (cross-family by default; null means the caller keeps `judgeProvider`; with a `strength` option, issue #38, never a weaker reviewer: stronger before equal before unknown tier, another family first within each, a local model below any cloud one; `teamStrengthOf` reads the tier from the model tier table), and `reviewEnabled` / `reviewPassesOf` (issue #38: `team.review` wins, listed reviewers turn review on, else `fusion.judge`; passes default 2), and `watchEveryMinutesOf` / `watchMaxChecksOf` (issue #43: minutes between a running task's progress checks, default 5, 0 off, 0 without a team; judge calls per watched task, default 3). They read no config or state. [Team reachability](team-reachability.ts) is the live side the runtime, the TUI's pickers and `fusion.delegate` share (`connectRuntimeProviders().teamMemberReachable`): registered, and a subscription CLI not known to be missing or signed out, from a cache checked in the background (`checkSubscriptionCli`, the `providers status` check, at start and when a read finds it older than five minutes), never awaited by a turn; unchecked counts as reachable.

`resolveRunMode(resolved, { director, worker })` takes a session's director (issue #37): with the stored mode `fusion` and its provider configured, it is the orchestrator leg (`orchestratorModel` is its model, `director` is set) and fusion is effective without `activeTextProvider` naming it. Legs are then compared as members (provider and model), so a director and a worker on one CLI stay two legs; a preferred `worker` that is the director is ignored.

Legacy Fusion legs use the configured model for requests when their provider serves multiple models. The orchestrator pin applies to its fallback link only. Workers and role tasks use their assigned model, and judge and escalation calls use their resolved target. Managed llama-server uses its loaded model. A shared provider can handle escalation between different models. `/runmode status` names the automatic target when configured.
