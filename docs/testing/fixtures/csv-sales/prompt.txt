Build an offline Node.js CSV sales summarizer as a fusion project, with the program and its tests as two separate worker tasks. The program is sales.cjs in this folder: CommonJS, Node built-ins only, no network and no dependencies, run as `node sales.cjs <input.csv>`. The first line of the input must be exactly sku,qty,price_cents (a trailing carriage return is allowed); otherwise print an error containing "Invalid header" to stderr, print nothing on stdout and exit 1. Every later non-blank line has exactly three comma-separated fields: a non-empty sku, then qty and price_cents as non-negative whole numbers written in decimal digits only, with any number of digits (a single qty or price_cents may itself be larger than Number.MAX_SAFE_INTEGER). Blank lines (empty or only whitespace) after the header are skipped, between rows and at the end, several in a row included, but they are still counted. For any other row (a negative, fractional, non-numeric or missing number, or the wrong number of fields) print an error containing "Invalid row N" to stderr, where N is its physical line number in the file (the header is line 1 and every blank line counts), print nothing on stdout and exit 1. On success print one JSON object on stdout that maps each sku to its total revenue in cents (the sum of qty times price_cents over its rows, an integer; any sku text must work, including toString and __proto__) and exit 0. The limit applies only to each sku's accumulated total: a total up to and including Number.MAX_SAFE_INTEGER is valid, the row that takes a total above it is an invalid row, and a row whose qty or price_cents is 0 adds exactly zero however large the other number is. The tests are sales.test.cjs, run with `node --test sales.test.cjs`, and cover repeated skus, zero values, skus named toString and __proto__ (read the output with JSON.parse), a wrong first line with no valid header before it, invalid numbers, blank lines between and after the rows, the line number of an invalid row after a blank line, a zero price with a huge qty and the reverse, and totals exactly at and one past Number.MAX_SAFE_INTEGER. Run `node --test sales.test.cjs` and get the configured reviewer's verdict on each task before you report the milestone.
